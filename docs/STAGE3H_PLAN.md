# Stage 3H: longer saved-position diagnosis

Authorized 22 October 2026 after the user requested a longer version of the Stage 3G review's proposed diagnosis. This is a separate read-only experiment. It has a 1,200-second cumulative numerical ceiling, not a requirement to consume the entire allowance. Stage 3G's negative results remain unchanged.

## Question and fixed scope

Determine how resetting the scorer and the four archived learning trajectories changed decisions, collection support, fitted targets and gradients. Compare the original reference, the common reset initialization, and updates 100, 200, 300 and 400 from each of the four arms: eighteen weight sets. There are no new games, optimizer steps, checkpoint writes or policy promotions. Average-rank utility remains `[1.5, 0.5, -0.5, -1.5]`.

Before outcomes, order each corpus split by SHA-256 of `riichi-ai/stage3h/v1|<split>|<match_id>`. Initially request 128 complete training matches and 128 development matches. Include every optional decision made by the designated explorer in each selected match. Other seats remain auditor-only. A separate existing sixteen-match preflight corpus supplies 64 hash-selected eligible rows per match, for 1,024 throughput positions. No fresh data is collected.

Choose the largest measured feasible split size from 128, 96 and 64 per split, in that order, before formal diagnostic outcomes. Fix the selected IDs, exact row counts, input hashes, source hashes and forecast in the final execution plan. If even 64 per split does not fit, stop before formal inference. Never reduce the panel after inspecting its results.

## Inference and measurements

Use fourteen independent CPU workers, one Torch thread each. Load the eighteen models once per worker and forward one decision at a time, matching deployed CPU float32 inference and legal-candidate padding. Compare tensors and scores with production collation on sixteen preflight rows for both reference and initialization. Retain every legal score, original row index, explicit hand ordinal, action kind, logged action and recorded behavior probability.

For each checkpoint, report raw argmax, the first-legal-win wrapper and the actual deployed action rule. The reference uses original argmax; value candidates use the wrapper. Report agreement with reference, initialization and logged actions; reference-to-candidate action-kind transitions; support under the recorded behavior distribution; legal score spread and top-two margin; and chosen-action errors against each available declared target. Original reference outputs are policy logits and must not be evaluated as utility predictions. The behavior-probability buckets are zero, `(0,.01]`, `(.01,.05]`, `(.05,.2]`, and `(.2,1]`.

Separate training and development, row means and means of within-match means. Report support counts for all positions and discard, call, riichi, kan, win and call-versus-noncall opportunity slices. Slice match means include only matches with that opportunity. A score gap is not regret; the logged outcome does not reveal the outcome of an unchosen action. These positions were generated by archived behavior, not the candidate policies' new trajectories.

## Gradient diagnosis

Use the first 64 selected training matches as four disjoint groups of sixteen. Separate the complete-match-weighted MSE and chosen-action cross-entropy gradients at six conditions: initialization with terminal targets; initialization with hand-difference targets; and each final arm with its own target. No optimizer is instantiated. Keep the rank head frozen and verify parameter hashes before and after each group.

Measure component norms, cosine alignment, combined alpha-zero/one norms and the archived norm-one clipping factor. Report backbone, scalar scorer and additive efficiency branch separately. Describe cancellation across the four groups without interpreting this small fixed sample as population signal-to-noise. Save raw float32 gradient vectors and their parameter layout for independent arithmetic audit. Compare the first initial terminal-target group on CPU and MPS before admission, using relative gradient L2 tolerance .01 and scaled objective absolute tolerance .001.

## Admission, integrity and stopping

The exclusive ledger charges all model, engine, numerical analysis and test subprocesses. Cumulative phase ceilings are 120 seconds for preparation/preflight/tests, 600 for inference, 300 for gradients and 120 for audit, with 60 seconds reserved for shutdown. Inference admission protects the entire remaining gradient and audit reservations. Use a twofold measured-work allowance plus startup/reporting capacity; the final admission file records the calculation. New artifacts stay under 1 GB, sampled process-tree RSS under 32 GiB, and free disk above 10 GB. A failed formal operation stops later formal work; audit and truthful closure remain permitted.

Inputs and sources are hashed and retained. All Stage 3G evidence is preserved against its completed commit and manifest; shared project documentation may evolve while its old bytes remain recoverable from that commit. Bulk output is outside iCloud in the local `RiichiAI/stage3h` evidence directory. Dependency versions accompany the ledger receipts.

An independent auditor reconstructs all saved numeric metrics and gradient-vector arithmetic from the recorded arrays and original shards. It also repeats inference on a fixed 576-forward panel: the first eight selected matches in each split, the first two eligible rows in each, and all eighteen weight sets. This small forward audit checks score authenticity; it is not a new playing-strength evaluation or independent rule certification.
