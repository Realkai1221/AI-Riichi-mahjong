# Stage 3F review and proposed first value-learning round

22 October 2026. This review distinguishes the completed engineering work from the next learning experiment, which has not started. The original external proposal remains preserved in STAGE3F_PROGRAM_PROPOSAL.md; the adopted execution scope is [STAGE3F_PROGRAM.md](STAGE3F_PROGRAM.md).

## What this stage changes

The saved-data diagnosis found a functioning implementation with a weak route to changing decisions. The first complete Stage 3E batch reconstructs, including its gradients and Adam movement. Only two of its sixteen matches supplied meaningful signal to the conditional call head. Gate gradients partly cancelled across matches, and the approximately 5% call gate attenuated conditional-head output changes. Some previously reported nonzero gradients were only floating-point residue. This supports changing the learning design; it does not identify a single statistically proven cause of failure. Read the [diagnostic review](STAGE3F_DIAGNOSIS_REVIEW.md).

The new collector completed a fixed 1,000-match development pilot with 646,377 recorded decisions in 86.915 seconds. Fourteen workers achieved 11.505 complete recorded matches/s. Serial and parallel executions of sixteen identical plans produced identical deterministic payloads. This is measured full collection, including serialization, rather than an inference-only speed estimate.

The bounded loader makes larger data practical without loading it all into memory. The pilot's numerical arrays occupy 2.476 GB uncompressed; the loader probe used a peak 5.465 MB of working arrays. Its sampled process RSS, including models and backend allocations, was 717 MB. The real actor backbone and a freshly initialized scalar action scorer processed about 1,086 rows/s on CPU and 3,286 rows/s on MPS, including loading, transfer, forward and backward computation. CPU/MPS values and gradients passed the declared checks. These short, zero-update probes exclude optimizer work and do not establish long-run training stability.

No model learned from these pilot games. No policy was promoted, and no playing-strength gain is claimed. The pilot stays development-only; it must not quietly become the next training or confirmation set.

## Keep, change and defer from the proposal

| Proposal | Decision and reason |
|---|---|
| Broader exploring collection | Keep. It supplies real sampled actions with their actual behavior probabilities, complete-match outcomes and reproducible seat assignments. |
| Parallel collection and streaming | Keep. Both now have measurements and reproducibility checks on this Mac. |
| Action-value learning | Keep as the next experiment. Use terminal rank utility as a clear control and test any hand-level surrogate separately. |
| Placement predictor / GRP | Keep conditionally. Cross-fit training potentials and check probability and expected-utility calibration before using them as targets. The old rank head is unsuitable as an assumed calibrated predictor. |
| Conservative penalty | Test against alpha zero. Here the term is algebraically chosen-action cross-entropy and may help through imitation regularization. A CQL-shaped term on Monte Carlo regression has no automatic Bellman-value guarantee. |
| Pool all four seats into one value fit | Change. Use explorer decisions first. At these tables a player's behavior also determines which other three behaviors it faces; all-seat pooling mixes both continuation policies and opponent populations. |
| Three 30,000-match rounds immediately | Defer. Collection is feasible, but end-to-end optimization, calibration and confirmation costs still need a measured learning run. |
| Explanation that earlier PPO plateaued | Reject. PPO has not run. The earlier experiments used REINFORCE and restricted call-head updates. |
| Books as ready training examples | Defer. The supplied books are present, but partial scenarios still lack sufficient state and action reconstruction. Their explanations remain attributed source advice, not certified full-match optima. |

## Proposed Stage 3G scope — not started

Use a fresh, fixed **4,000-match corpus**, split by complete match before outcomes into **3,200 training and 800 development matches**. Retain the same declared three fixed opponents for the explorer, with frozen seat permutations and independent RNG streams. Save all seats for audit, but fit action values only to the explorer's optional decisions. Preserve forced decisions and final rewards in the records. Do not use Stage 3F pilot outcomes or historical confirmation games for final evaluation.

Use complete-match weighting: first average eligible row losses within each match, then average matches. The proposed loss is `mean_match mean_optional[(Q_taken - target)^2 + alpha * (logsumexp_legal(Q) - Q_taken)]`, with both targets kept in their declared utility units. A practical implementation can accumulate gradients over fixed groups of sixteen complete matches before one optimizer step. Account for variable row counts and the final partial tensor batch explicitly. If a match has no optional explorer rows, assign zero numerator with the fixed match denominator and report it; do not silently reweight the remaining matches. Match-local shuffling is acceptable for this first controlled experiment; it is not global IID sampling.

Start from the same reference backbone with an identically initialized scalar action head for every arm. Train the actor backbone and action head; keep the old rank head unused. Preserve only audited player-visible inputs, legal masks and average-rank utility `[1.5, 0.5, -0.5, -1.5]`. Do not feed final outcomes, policy identifiers, opponent hidden hands or auditor logs into the actor. Keep the collector's deterministic legal-win rule explicit in the eventual candidate action policy.

Compare four arms: terminal utility versus the explicitly defined one-hand placement-potential difference, each with conservative-penalty alpha **0 or 1**. Freeze a common initialization, match order, optimizer recipe and **two full training passes per arm**. With sixteen-match accumulation this implies 400 scheduled updates per arm; an entirely empty group must be recorded as a no-gradient step without optimizer movement. A single initialization is a mechanism experiment, not robust evidence across training seeds.

For placement potentials, fit a small separate predictor from allowed public summaries. Use five folds grouped by complete match for out-of-fold training potentials, then fit the declared final predictor on training data for development inference: budget **six fits**, plus any separately fitted baseline. Substitute exact terminal utility only at true match termination. Predicting from a next-hand state must not include that hand's future events. Report NLL, Brier score, classwise calibration and expected-utility error by match stage, using game-clustered uncertainty. Compare proper scores against a declared simple public-score baseline and utility calibration in fixed prediction bins; small overall mean bias is insufficient. Specify thresholds, minimum unique-match counts and early/sparse-stratum treatment before fitting; if that gate fails, stop the shaped-target arms and report an incomplete factorial experiment. The terminal-utility controls may continue only under that predeclared fallback. Do not select whichever target happens to look good and call the comparison complete.

Define the hand target exactly as `V_fold(next_hand_start) - V_fold(current_hand_start)`, substituting the actual utility at true match termination and using the same held-out predictor at both ends. Associate it with decisions in that explicit hand ordinal, including dealer continuations. The one-hand difference is a surrogate objective, not the full return from the current decision. Likewise, Monte Carlo labels reflect the explorer's recorded continuation and fixed opponents; the greedy policy extracted from fitted values changes that continuation. Behavior probabilities make collection auditable but do not automatically correct this mismatch. Fresh game evaluation remains necessary.

Before the learning run, freeze a **7,200-second numerical cap** with separate reservations for corpus collection, cross-fitting/calibration, all four arms, development games, final audit and shutdown. The short MPS measurement is a planning input, not a guaranteed completion rate. Confirm and time the actual explorer-filtered, match-accumulated MPS Adam update and resume against CPU first; if MPS fails, recompute feasibility before collecting the formal corpus. Do not silently shrink a completed arm's exposure or extend the fixed sample based on outcomes.

Use common fresh game utility to choose one candidate; raw validation losses for different targets are not comparable selection scores. A concrete development panel is **64 shared blocks, four seat rotations, four candidates plus one shared original-reference baseline: 1,280 games** if all arms pass their gates. Reserve those games separately from the 4,000 corpus matches. Freeze physical-wall commitments, a tie order beginning with terminal utility / alpha zero, action safety checks and the calibration-failure fallback before outcomes. Descriptive development advantage is selection evidence only. A fresh paired confirmation against the unchanged original reference should be a separately frozen follow-on, with its own seed blocks, confidence rule and power/budget calculation. The proposed learning round alone cannot establish world-class strength.

The pilot's explorer supplied 149,235 optional rows per 1,000 matches. A linear planning estimate gives about 477,552 training rows for 3,200 matches and 3.82 million row presentations across four arms and two passes. At the short MPS rate this is approximately 19.4 minutes of loader/forward/backward work, or 38.8 minutes with a twofold allowance, before optimizer, calibration, tests, collection and evaluation. The executable plan must reserve each of those costs and admit the whole fixed experiment before starting.

The current opponent panel is narrow: none of the three other behaviors called in this pilot. There were only two added-kan examples even across 1,000 games. Broader opponent policies and deliberate rare-state fixtures remain later requirements; these data cannot establish strong defense against expert calling strategies or reliable value estimates for rare kans.

## Longer-term scale

At the measured pilot rate, 30,000 matches would take about 43.5 minutes to collect, before thermal, scheduling and workload variation. Linear storage extrapolation is approximately 8.35 GB for compressed match artifacts and 74.3 GB for uncompressed numerical arrays. Those are forecasts, not observed 30,000-match results. Streaming is necessary on a 64 GB machine, and training several targets, alphas and seeds is a separate cost.

Continue using this Mac for data engineering, controlled small learning rounds and reproducible evaluation. The present evidence does not justify paid hardware or a larger model. CUDA remains a portable path with no local CUDA measurement. The next useful result is a stable value learner whose behavior changes in interpretable ways, followed by fresh competitive evidence.
